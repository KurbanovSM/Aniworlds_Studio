# Правила разработки Aniworlds Studio

Перед изменением обязательно читаются этот документ, `docs/architecture.md`,
`docs/game-integration-notes.md`, актуальный серверный контракт и все упоминания
затрагиваемого поведения.

- Одно правило имеет одну реализацию. UI только собирает ввод и вызывает
  проверяемую прикладную функцию.
- Studio не подключается к VPS, базе данных или Telegram и не хранит их адреса.
- Экспорт всегда проходит через строгий контракт и сохраняется локально.
- Промокод и технические поля создаются программой; пользователь меняет только
  разрешённые продуктом значения.
- Нельзя молча перезаписывать существующий экспортированный файл. Единственный
  заменяемый файл глобальных настроек требует отдельного подтверждения в UI.
- Открытие опубликованного мира создаёт редактируемое состояние в памяти. Любое
  последующее сохранение требует нового пути и не изменяет исходный файл.
- Production-файл содержит не более 300 строк, класс — 240, функция — 120.
- После изменения обязательны Ruff, Pyright, Pytest с покрытием прикладной логики
  не ниже 90% и проверка совместимости результата с серверным импортёром
  Aniworlds AI. Тонкий Tkinter-адаптер и точка запуска в покрытие не входят.
- Несовпадение Studio и игры нельзя обходить скрытым преобразованием ID или
  отбрасыванием данных. Оно фиксируется явно и выносится в отдельный аудит цепочки
  `документы → экспорт Studio → серверный контракт → импорт → база данных`.
- Код Studio хранит только формы, схемы и правила проверки. Конкретные расы,
  виды, языки, объединения, миры, периоды, персонажи, локации, предметы и наборы
  являются авторскими данными и не встраиваются в Python как начальные,
  демонстрационные или резервные записи.
- Общая карточка расы, языка или объединения публикуется ровно один раз в
  `global-catalogs.catalog.json`. Мир может хранить только её ID и мировые связи;
  копирование основных полей в пакет мира запрещено.
- Публикация в GitHub выполняется только после успешных проверок.

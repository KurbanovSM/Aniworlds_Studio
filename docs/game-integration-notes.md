# Обязательная редакция Aniworlds AI для общих каталогов

Studio и Aniworlds AI используют согласованный отдельный серверный артефакт общих
каталогов и пакеты миров версии 4. Этот документ фиксирует обязательный порядок
загрузки и импорта; файлы нельзя заменять частично в обход единой операции.

## Новый порядок импорта

Сервер должен читать локальное дерево в порядке:

1. `settings/global-gameplay.settings.json`;
2. `catalogs/global-catalogs.catalog.json`;
3. отдельные файлы `worlds/*.world.json`;
4. отдельные файлы `promocodes/<CODE>.json`.

## Владение авторским контентом

Конкретные расы, виды, объединения, черты характера, миры, периоды,
персонажи, локации, предметы, магазины и стартовые наборы создаются в Studio. Игра получает их только
из опубликованных файлов и не хранит в коде начальный, демонстрационный или
резервный список. Studio также не встраивает конкретные карточки в Python:
начальное состояние берётся из редактируемого файла данных и может быть полностью
изменено автором до публикации.

Исторические миграции игры не переписываются, но их старые начальные записи не
считаются актуальным каталогом. Переход должен отдельной новой миграцией и
импортёром устранить зависимость работающей игры от этих записей.

Общий каталог имеет `artifact_type = aniworlds.global_catalogs` и
`schema_version = 2`. Полные карточки видов и рас, объединений и черт
характера находятся только в нём.

## Новый контракт мира

`aniworlds.world_foundation` версии 4 не содержит полных массивов
`creature_kinds` и `groups`. Вместо них используются:

- `creature_kind_settings`: `creature_kind_id`, места обитания и
  доступные периоды конкретного мира;
- `group_settings`: `group_id`, локации, союзники, противники и состояния по
  периодам конкретного мира.

Локации версии 4 находятся один раз в корневом массиве `locations`, включая
коэффициент цен. Периоды ссылаются на них через `location_ids`,
`starting_location_ids` и `location_connections`; вложенные копии локаций не
используются.

Импорт обязан сначала проверить существование каждого ID в общем каталоге, затем
сохранить только мировые связи. Название, описание, категория, мышление, способы
общения и другие основные поля копироваться в таблицы мира не должны.

## Реализованное хранение игры

- Базовые виды и расы вынесены из владения одной вселенной в общую таблицу.
- Устранён конфликт, при котором `world_creature_kinds.id` одновременно являлся
  глобальным первичным ключом и запись содержит `universe_id`.
- Созданы таблицы связи мира с расой и отдельные таблицы её мировых настроек.
- Механика языков удалена из текущих контрактов Studio и игры.
- Основная карточка объединения отделена от его состояния в конкретном мире.
- Черты характера хранятся общей карточкой с ID, названием, объяснением и
  взаимными связями несовместимости; подготовленные NPC ссылаются на те же ID.
- Добавлена новая миграция; исторические миграции не переписаны.

## Создание персонажа

`GET /api/v1/character-editor` берёт полные расы и черты из общих таблиц.
Если игрок выбирает принадлежность к вселенной, сервер и Mini App должны оставлять
только записи, связанные с этой вселенной. Для персонажа без принадлежности
показываются все опубликованные записи, связанные хотя бы с одним опубликованным
миром.

## Приёмка

- Один ID расы используется несколькими мирами без дублирования основной записи.
- Изменение общей карточки отражается во всех мирах.
- Удаление используемой общей записи запрещено понятной ошибкой.
- Мир с неизвестным ID не импортируется целиком.
- Подготовленный NPC с неизвестной или несовместимой чертой не импортируется.
- Рассказчик получает название и объяснение выбранной черты вместе с ID.
- Повторный импорт каталогов и миров идемпотентен.
- Старый пакет версии 3 отклоняется строгой проверкой версии; скрытого
  преобразования формата нет.
# Карточки генерации NPC

Не загружайте отдельно списки имён. Они входят в `*.world.json` вместе с миром.
Сначала установите версию игры, которая знает поля `npc_name_sets`,
`npc_biographies` и `npc_generation_rules`, затем опубликуйте черновик Studio и
импортируйте полный пакет мира обычным атомарным импортом. Старые пакеты версии 4
без этих необязательных полей остаются допустимыми. Полные списки хранятся в JSONB
пакета и не отправляются модели при каждом ходе.
Сначала обновляется код игры, затем Studio заново публикует полный пакет из
актуального черновика. Старые серверные пакеты не хранятся в репозитории.
Черновик расширенного мира v4 содержит 30 локаций с координатами схемы,
50 подготовленных персонажей и диапазон стартовой валюты NPC 0–10000.

Поля `npc_starting_currency_min` и `npc_starting_currency_max` находятся в
карточке экономики мира. Сервер один раз создаёт кошелёк каждого нового NPC со
случайным балансом внутри включительного диапазона и больше его не перебрасывает.
У локации `map_x` и `map_y` задают точку на схеме от 0 до 1000; нужны либо обе
координаты, либо ни одной. Старый пакет без координат остаётся допустимым.
